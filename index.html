How the mediator works

This site is the single network dependency for marketplace data — the app boot fetches the mandatory core config, then merges the registry.

01

Private repo builds

The FocusCaseX app repo runs scripts/sync-marketplace.mts: its catalog modules and disk assets are compiled into api/registry.json + api/core.json.

02

Public repo publishes

The generated JSON and asset copies are pushed here. GitHub Pages serves them globally with Access-Control-Allow-Origin: * — a free CDN-backed API.

03

App loads core

Every FocusCaseX boot fetches api/core.json (cached, stale-while-revalidate). Flags, featured picks and announcements apply without a redeploy.

04

Marketplace stays fresh

The in-app store merges api/registry.json and badges items whose remote version is newer — tap to pull the update straight from this site.

API reference

Static JSON endpoints on this Pages site. No auth, no rate limits beyond GitHub's generous Pages cache.

EndpointReturnsNotes
GET /api/core.json Mandatory core config — schema fcx.market.core.v1: version, minAppVersion, flags, announcement, featured, autoEnableCapsules Fetched at every app boot; changes here propagate to all clients on next launch
GET /api/registry.json Full catalog — schema fcx.market.registry.v1: counts, items[] (MarketItem contract + files), snippets[] Merged into the in-app Marketplace; versions drive update badges
GET /capsules/<id>/* Raw capsule layers — spec.mdui, style.css, logic.mdui Linked from each registry item's files map
GET /plugins/<id>/* Plugin bundle — manifest.json + main.js Installable / updatable from the in-app store
GET /themes/<id>.json · GET /templates/<id>.md · GET /snippets/* Theme token JSON · template markdown · CSS snippets Themes apply instantly; templates create pages; snippets are copy-in CSS
