API & update system

This site is also a static, versioned JSON API. Every FocusCaseX client reads it on boot — the app never depends on a private repo for updates.

core · fetched every boot
GET https://stromplayz.github.io/FocusCaseX-Marketplace/api/core.json

The mandatory core config: version, feature flags, the announcement and the list of core plugin files the in-app updater pulls after the user confirms.

registry · the catalog
GET https://stromplayz.github.io/FocusCaseX-Marketplace/api/registry.json

Every published item with metadata and a files map. The app merges it into its in-app Marketplace and drives install / update badges from remote versions.

assets · pulled on demand
GET …/plugins/core-ui/main.js · …/capsules/ui-exam/spec.mdui

Raw files fetched only when an install or update needs them. Publish here and every client can pull it — nothing is bundled into an app release.

FAQ

Short answers to the questions clinics actually ask.

Is everything here free?

Yes. Every listing is published as a static file on GitHub Pages and installs at no cost. The marketplace is part of the open FocusCaseX ecosystem.

Do I need this website to install anything?

No — the whole catalog is inside the app under Marketplace. This site is the browsable, shareable mirror of it and the delivery network the app downloads from.

How do updates reach my device?

On boot the app checks api/core.json and the registry. If the mandatory core moved forward, you get a confirmation prompt before anything downloads; regular items show update badges in the in-app Marketplace.

What are capsules vs extensions vs templates?

Extensions add commands, panels and behavior. Capsules are building blocks — ready-made UI pieces like the appointment board or patient directory that render inside your pages. Themes restyle the workspace. Templates are clinical markdown starters (intake forms, letters, workups).

How does an item get published here?

Items are generated from catalog.json in the FocusCaseX-Marketplace repository and synced from the main repo by a publish script. The registry you see is regenerated on every sync.
