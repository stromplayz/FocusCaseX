The public extension hub for FocusCaseX — capsules, plugins, themes and templates live here, and this site doubles as the API mediator: a static, versioned JSON API every FocusCaseX client reads on boot. The app never depends on its own private repo for updates — it pulls from here.

The API mediator

Two static endpoints drive the whole update story. The core is fetched on every app boot (stale-while-revalidate) and carries feature flags, announcements, featured picks and the mandatory core plugin list.

core · mandatory · fetched every boot GET https://stromplayz.github.io/FocusCaseX-Marketplace/api/core.json

The mandatory core config — version, flags, the announcement (with its CTA), and corePlugins: the files the in-app core-updater pulls when the user confirms.

registry · the catalog GET https://stromplayz.github.io/FocusCaseX-Marketplace/api/registry.json

Every published item with its metadata and a files map — the app merges it into its in-app Marketplace and drives install / update badges from remote versions.

assets · pulled on demand GET …/plugins/core-ui/main.js · …/capsules/ui-exam/spec.mdui · …/themes/midnight.json

Raw files, fetched only when an install or update needs them. Nothing is bundled into the app release cycle — publish here and every client can pull it.

How the core update flows

STEP 01

Announce

The core-announcement surface renders a pixel-art banner in the app with the update title and a CTA.

STEP 02

Confirm

The user taps “Download Update v2” — nothing is pulled without the user's confirmation.

STEP 03

Pull

The core-updater re-checks the core, fetches every core plugin + core CSS from this site.

STEP 04

Apply

Plugins land on disk (or in-memory on read-only hosts), flip on, and the core version is stamped.
