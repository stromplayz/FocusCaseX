For developers

The catalog API

The marketplace is plain static files — every FocusCaseX client reads the same JSON you see below.

No database, no auth, no rate limits. Just files on GitHub Pages.

Endpoints

Every path below is a real file at the site root. Point any HTTP client at them, or just open them in a browser.

catalog.json
The full catalog — 71 items across extensions, capsules, themes and templates, plus the snippets list
releases.json
App release history — version, versionCode, core and notes for every build
api/registry.json
Generated plugin registry — the index every client merges at boot
api/core.json
Current core version, minimum app version, announcement and featured picks
themes/<id>.json
Theme palettes — the vars each theme applies to the workspace
templates/<id>.md
Template bodies — raw markdown, fetched and rendered on demand
plugins/<id>/
Extension sources — manifest.json and main.js per folder
capsules/<id>/
Capsule layers — spec.mdui, style.css and logic.mdui, varying by capsule
snippets/<id>.css
Small CSS snippets, referenced by the snippets list in catalog.json

Catalog shape

One real entry from catalog.json, compacted. Every item carries the same fields:

{ "id": "plugin:note-templates", "kind": "plugin", "name": "Note Templates", "tagline": "Inserts a dated checklist template at the end of the active note with one command.", "description": "Inserts a dated checklist template at the end of the active note with one command.", "author": "FocusCaseX originals", "version": "1.0.0", "category": "Writing", "tags": ["plugin", "writing"], "icon": "FileText", "released": "2026-01-24", "verified": true, "featured": false, "meta": { "pluginId": "note-templates" }, "files": { "manifest": "plugins/note-templates/manifest.json", "main": "plugins/note-templates/main.js" } }

How updates work

At boot, the app fetches catalog.json and merges the generated index in api/registry.json, so the Android app, the hosted workspace and this site all read the same list of items.

Version checks compare the installed build against the newest entry in releases.json; the current core version and its minimum app version live in api/core.json.

The registry is rebuilt by scripts/build-registry.mjs on every push. CI re-runs the script, validates that the catalog and core files still parse, and fails the build if a committed registry is stale.

Publishing

There is no toolchain to learn. If the files exist and the JSON parses, the change ships.

  1. Fork the repository, or open a branch on your copy.
  2. Commit your assets: a new entry in catalog.json plus the files it points to — plugins/<id>/, capsules/<id>/, themes/<id>.json or templates/<id>.md.
  3. CI validates the catalog and the registry, and GitHub Pages serves the change — it is live the moment the push lands.
